# YouHost

YouHost is a free, open-source live plugin host for macOS. It is aimed at front-of-house work: pick an audio interface (from a stereo pair up to 128 channels, such as a Behringer X32 USB 32×32 or a Klark Teknik DN32-USB), send each input back out of the same-numbered output, and insert up to four plugins on each channel.

This build opens the device, passes input *n* to output *n*, records a WAV for each armed channel, and hosts AU and VST3 plugins in-process. Scanning runs in a child process so a plugin that crashes while being identified does not take the mixer down. Playback is not sandboxed yet: a plugin can still crash the app while it is loaded. The slot graph is the piece a later sandbox can replace.

YouHost is [AGPLv3](LICENSE). It is built with [JUCE 9.0.3](https://github.com/juce-framework/JUCE/releases/tag/9.0.3) under JUCE's AGPLv3 option, so the app costs nothing to build or run.

## Suomeksi

YouHost on ilmainen avoimen lähdekoodin (AGPLv3) plugin-hosti Macille, livekäyttöön. Sisääntulo *n* menee ulostuloon *n*, ja jokaisella kanavalla on neljä plugin-paikkaa sarjassa (AU ja VST3). Skannaus tapahtuu erillisissä prosesseissa, useita kerrallaan, ja jumittunut skanneri tapetaan. Waves-shellit ohitetaan oletuksena. Mittari käynnistyy aina RMS-tilaan. Käynnistyksessä valitaan ensin äänikortti sekä session nimi ja kansio (yleensä ulkoiselle levylle). Kansio, jossa ovat `session.youhost` ja `audio/`, luodaan ennen nauhoitusta. Sisäinen levy (`~/Music/YouHost`) on vain erillinen varoituspainike. Nauhoitus kirjoittaa WAV-tiedostot session `audio/`-kansioon. Record-painike vain virittää oton ja vilkkuu. Play viritettynä aloittaa nauhoituksen. Play ilman viritystä on soundcheck. Cmd+Space nauhoittaa heti. Stop lopettaa ja riisuu virityksen. T lähentää aikajanaa ja R loitontaa. Stop jättää otot aikajanalle, ja ne tallentuvat `session.youhost`-tiedostoon. Space soittaa tai pysäyttää, ja viritettynä se aloittaa nauhoituksen. Toisto on virtuaalinen soundcheck: jokainen päällä oleva nauhoitettu kanava, myös ilman plugineja, menee samaan USB-lähtöön ja latenssikorjaus pitää lähdöt yhdessä. REC-painike sammuttaa kanavan heti (mittari, pluginit ja lähtö). Käynnissä olevan oton tiedostot eivät vaihdu. Kanavavärit ja ryhmät ovat X32:n värejä, ja ne ovat vain näkymää. Aikajana näkyy myös plugin-sivulla. Dropout-ikkuna aukeaa näppäimellä 4 tai D, ja sen Reset nollaa laskurin mutta jättää CSV-lokin.

Valmis `YouHost.app` ladataan GitHub Actionsin artefaktina tai version mukana Releasena. macOS Sequoia ei avaa allekirjoittamatonta sovellusta Control-klikkauksella. Avaa YouHost kerran, mene sitten kohtaan **Järjestelmäasetukset → Tietosuoja ja suojaus → Avaa silti** ja vahvista salasanalla. Tai poista karanteeni päätteessä: `xattr -dr com.apple.quarantine YouHost.app`. Mikrofonilupa tarvitaan myös USB-mikserille: **Järjestelmäasetukset → Tietosuoja ja suojaus → Mikrofoni**.

## Download a build

Public builds come from GitHub Actions on a free macOS runner. Each successful run on `main` and on a pull request produces one universal app (Apple silicon and Intel).

1. Open the [Actions tab](https://github.com/PaanisYouHost/YouHost/actions/workflows/build-macos.yml).
2. Choose the newest green **Build YouHost** run.
3. Download the artifact named **YouHost-macOS-universal**.
4. Unzip it. GitHub wraps the artifact, so you may need to unzip twice until you see `YouHost.app`.

When a tag named `v*` is pushed (for example `v0.1.0`), the same zip is attached to the [GitHub Release](https://github.com/PaanisYouHost/YouHost/releases) for that tag. That download is a single zip with `YouHost.app` inside.

The app is ad-hoc signed and does **not** use the Hardened Runtime. That is deliberate: this build loads other developers' VST3 and AU binaries. There is no Apple Developer ID and no notarization, so Gatekeeper will quarantine a downloaded copy.

## Open it on macOS Sequoia

Sequoia removed the old Control-click → Open bypass.

1. Double-click `YouHost.app`. macOS will say it cannot be opened.
2. Open **System Settings → Privacy & Security**.
3. Near the bottom, choose **Open Anyway**, then confirm with an administrator password.
4. The next double-click asks once more. Choose **Open**.

The same thing from Terminal, in the folder that contains the app:

```bash
xattr -dr com.apple.quarantine YouHost.app
open YouHost.app
```

macOS then asks for microphone access. USB interfaces, including the X32, are behind that same switch. If the meters stay dark, check **System Settings → Privacy & Security → Microphone** and turn YouHost on. Ad-hoc signatures change every build, so each downloaded build asks again.

Quit with the window's close button, or YouHost → Quit.

## What this build does

On launch YouHost shows a startup window before the mixer. Pick the audio interface, sample rate, and buffer size there, then create a new session or open an existing one. The meter mode is always RMS, even if Peak was selected last time. Peak comes back only when you open a session that was saved that way.

- The startup window asks for the input and output device, sample rate, and buffer size, and for the session. Up to 128 channels are requested, and the device clamps that to what it actually has, so an X32 or DN32-USB should come up as 32 in and 32 out. The device choice is saved and restored (on macOS, under `~/Library/Application Support/Ambient Audio/YouHost`). The channel ticks on the startup window open and close device channels. A new session needs a name and a folder. The folder starts in the last place you used. **Browse…** picks a drive or folder, and **Create session** writes `session.youhost` and `audio/` there before any recording. **Open existing…** and the recent list load a session instead. **Internal disk…** is the only way to store a dated folder under `~/Music/YouHost/`, and it warns first: recordings usually belong on an external drive. Closing the window without a session opens the mixer with **No session** and does not create a folder. The device panel's Test button is removed: JUCE's built-in tone is about -6 dBFS, which is far too loud on a live desk. Later, **Audio setup** shows the same device plus **Bit depth**. The green channel ticks in that later window are the same switch as **REC** / **OFF**. Unticking one turns that channel off in the app, and turning a channel off unticks it. The audio device stays open, so those ticks do not glitch the interface.
- The top bar starts on the left with **New**, **Open**, **Save**, **Audio setup**, and **File**, then **Group**, **All**, and **Hide**. Page buttons sit on the right, scanner first because it is rarely used: **SCAN**, **1 REC**, **2 HOST**, **3 DROPOUTS**, **4 CPU**, **5 LATENCY**. The active page and any open window stay highlighted. **Group** lists the ten groups; choosing one opens the rename and color menu. **All** opens every group. **Hide** folds channels that belong to a group. Transport (**Prev**, **Next**, **Stop**, **Play**, **Record**) and the time counter are centered on their row. **Record** is always red. **Play** is always green. **?** sits in the bottom-right corner. The same keys work when a text field does not have focus. Cmd+S still saves from the File menu and while a plugin window is in front.
- Live sound always passes through: input *n* goes to the plugins and then to output *n*, whether or not a take is recording. Recording only adds a copy of the raw input to disk. **Play** replaces the live input with the recorded take. **OFF** is the only switch that cuts a channel. The audio callback copies input *n* to output *n*, meters that signal, then runs that channel's plugins and the alignment delay. While a take is recording, the callback also copies the raw input into a lock-free ring. A disk thread writes the files. The callback does not allocate, take a lock, or log. If the disk falls behind, samples are dropped from the file and the audio keeps going. Loading and removing a plugin happens off the callback, and the new chain is swapped in as one snapshot.
- **Recorder.** A session is a folder with `session.youhost` and `audio/`. **New** and **File → New** ask for a name and a location, save the current session if it already has a folder, clear the takes, and keep the plugins. Cancel leaves the current session unchanged. The location starts in the last parent folder you chose. YouHost remembers that parent for the next new session, except a session stored under `~/Music/YouHost/`, which does not become the new default. If that drive is not mounted, the dialog says the last drive is not available and starts in `~/Music`. **Open** loads a different session. **Save** (Cmd+S) writes `session.youhost` immediately, from either page, from the menu bar, and while a plugin window is in front. With no session yet, Save, Save As, and Import ask for a name and a folder first, and they do not write anything if you cancel. **File** is the same menu as the macOS File menu: Open Recent (the last 10 sessions), Save As, Import Recording Folder, and Clear Timeline. **Save As**, when a session already exists, copies the whole folder, including `audio/`, and leaves the original where it was. **Import recording folder** copies WAVs into the current session (or opens the folder if it already contains `session.youhost`). New files are named channel first, with no zero padding: `1_1.wav`, `2_1.wav` for take 1, and `1_2.wav` for take 2. A renamed channel adds the name, for example `1_1_BD.wav`. A channel with no name does not get one stuck on. Older `Take01_Ch03_Kick.wav` names still import. **Audio setup** includes **Bit depth**: 16-bit, 24-bit (the default), or 32-bit float for the next take. The choice is shown there and in the top status line, and it is saved in the session. A take that is already recording keeps the depth it started with. Every channel starts on. The **REC** / **OFF** button under a meter is the channel switch. **OFF** cuts that channel immediately: nothing is metered, its plugins are skipped, and its output is silent. The WAV files already opened for the current take stay as they were. The transport **Record** button only arms the next take. It blinks red while armed and stopped, and it stays solid red while a take is recording. Clicking it during a take does nothing. **Play** while armed and stopped starts recording. **Play** while not armed is the virtual soundcheck. **Play** while already playing or recording does nothing. **Stop** ends the take and turns the arm off. Cmd+Space records immediately. If there is still no session folder, that press opens the name and location dialog and starts the take only after a folder is created. Cancel does not record. If the session drive is missing or the folder is not writable, YouHost warns and does not start the take. The next take uses the channel buttons as they are then, and only channels that are on and have an input get a mono WAV at the depth chosen in Audio setup. **Stop** leaves the take on the timeline. The session file is written straight away, with the WAV names, colors, and groups. The next recording appends another take on the same timeline, which always starts at 0. Take edges are marked. The timeline is about 2 cm tall on the recorder page, a little shorter on the plugins page, and it keeps that height when you open more channels. **T** zooms in and **R** zooms out. The **+** and **−** buttons at the bottom right of the timeline do the same. Zoom keeps the playhead on screen, and a horizontal scrollbar appears when the view is shorter than the session. During play or record the view follows the playhead only when it leaves the screen. Click or drag the timeline to move the playhead. The big counter is `hh:mm:ss`. It turns red and reads RECORD while recording, and it stays visible on the plugins page. Strips get narrower as the channel count grows, down to a width that can still show REC, and then the bridge scrolls sideways. The scale numbers sit next to the meters. When the bridge scrolls they stay pinned at the edges of the window. A line separates each strip. **Clear Timeline** asks first and removes the takes from the timeline. It does not delete the WAV files. The main window, scanner, dropouts, latency card, audio setup, plugin list, and plugin editors can be resized, and YouHost remembers their size and position.
- **Playback** is a virtual soundcheck. **Play**, when record is not armed, reads the takes from the playhead and sends every channel that is on to the same-numbered USB output, instead of the live input. A channel with no plugin stays dry. Channels that do have plugins run those plugins. Every included output is then delayed so it lines up with the slowest chain that is still on, including the dry ones. A channel set to OFF stays silent and does not pull the others late. PLAYBACK shows next to the counter. Channels that were not recorded are silent. Playback has to be at the same sample rate as the recording. Opening a session restores the takes, so Play works as soon as the device is at that rate.
- The recorder page is a dark meter bridge. Channel numbers follow the device (channel 1 is the first device channel). RMS uses about a 300 ms window. On that scale, 0 is line level: the **RMS 0** menu chooses -14, -18, or -20 dBFS (default -20, so the top tick is 0 dBFS and the scale reads +20 down to -40). **Peak** switches the bar to a full-scale sample peak with a 1.5 s hold, and the scale becomes dBFS with 0 at the top (0, -3, -6, -10, -20, -30, -40, -60). Faint lines cross the bridge at each mark. The 0 mark is a brighter, thicker line: line level in RMS, 0 dBFS in Peak. The numbers sit beside the meters. The meter bar is green below RMS 0 (line level, -20 dBFS by default), yellow from that point up to full scale, and red at 0 dBFS. Peak uses the same points on the full-scale ruler: green below the line-level mark, yellow above it, red at 0 dBFS. Changing **RMS 0** moves the green/yellow point in both modes. The channel number stays in bold under every strip, even when the name is long or the strip is narrow. A channel color tints the whole strip, with a solid bar of that color at the left. A sample at or above full scale lights the clip mark and leaves it on. Click that lit mark to clear the channel, or press **Clear clips**.
- **Plugins.** The same timeline, transport, and clock sit above the rows, a little shorter than on the recorder page. Channels are rows, 1 at the top. Each row has the number, a **REC** / **INPUT** / **OFF** button, a name (double-click to edit; the name is used in the WAV file name), a small meter, an **Ex** button, and four slots. The slots stay a fixed narrow width so a row does not stretch across the window. The channel number is bold and keeps its own width, so a long name cannot hide it. A channel color tints the whole row, including the slots. An empty slot opens a resizable plugin list grouped by manufacturer. Search matches a plugin name or a manufacturer, including part of a word, and opens that manufacturer's plugins. The list has All, AU, and VST3 at the top. The same plugin is listed twice, as `(AU)` and `(VST3)`, when both formats were scanned. Apple's built-in effects are included. Instruments and generators stay out of the list, and the list says so, until the scanner checkbox is on. Choosing a plugin loads it and opens its window. Loading, opening, and closing a plugin never waits on the audio thread: the chain is swapped in as one snapshot, and a plugin is paused only for the call that needs it. If the message thread or the audio thread stalls for more than 2 seconds, YouHost writes the phase and a stack to youhost.log. Channel chains run in parallel on the performance cores. Click the slot again to close the window, and again to reopen it. Drag a loaded slot onto another slot to move that same plugin. Option-drag copies it and its settings into a new instance. A drag is ignored while a plugin on that channel is still loading. Closing or unloading a plugin hides its editor immediately and deletes the editor, then the plugin, only after a few message-loop turns, so a remote Audio Unit view can finish opening. The label is the slot number plus the plugin name, for example `1 Pro-Q 3`. A loaded slot is green; bypass is dim. Right-click a slot for Open, Bypass, and Remove. Right-click the channel name for color, rename, and group. **Ex** means **Exclude from alignment**. Shift-click selects a range of channels.
- **Scanner.** **Scan** looks for new AU and VST3 plugins. AU plugins come from the AudioComponent registry, which includes `/Library/Audio/Plug-Ins/Components` and the user Library. VST3 plugins come from `/Library/Audio/Plug-Ins/VST3` and `~/Library/Audio/Plug-Ins/VST3`. Four scanner processes work at once. Each one is reused for a few ordinary plugins, then quit. A shell plugin gets its own process, which is killed when that plugin finishes. If a plugin is still going after 20 seconds (45 for a shell), it is killed, marked failed with the reason, and the scan moves on. Stuck scanners are not left running. **Rescan** only reopens plugins whose file time or AU version changed. **Stop** kills the current scanners. **Scan file…** checks one `.vst3` or `.component`. **Rescan selected** does that for the highlighted row. The progress bar shows `done / total`, the current plugin, and the elapsed time. Found and failed counts update while the scan runs. Failed rows include the reason. **Scan Waves shells** is off by default: one WaveShell lists hundreds of plugins and used to stall the scan before later plugins such as De-Feedback were reached. Turn it on when you want those Waves plugins; they are scanned last. Effects are listed, including Apple's Audio Units and VST3 plugins that did not report an input count. Instruments and generators stay out until **Show instruments in inserts** is on. Scanning runs at a lower priority, and only one scanner runs while the audio device is open. The scanner says that scanning may cause dropouts. A plugin dialog in a scanner process is closed when that plugin's timeout is reached. The scanner window itself still lists everything that was found. The header shows CPU use from the audio device.
- Each plugin reports its latency. **All aligned** (the default) lines every included channel up on the slowest one, so a dry channel next to a plugin is delayed by exactly that difference and the pair stays together. **Per group**, chosen in the **LATENCY** window, lines each group up on that group's own slowest plugin. Ungrouped channels are not delayed. A bypassed slot adds no latency. With no plugins the input is copied to the matching output and nothing else is done to it: no filter, no polarity flip, no dither, no sample-rate conversion, and no mix with a delayed copy. A plugin keeps the channel layout it opens with. One that opens stereo stays stereo on a mono channel: both inputs get the same samples, with no offset, and the output is the left side unless the slot menu says Use R or Sum (L+R)/2. One that opens mono stays mono. The choice, the latency, and a short level check are written to youhost.log. A short device callback is queued until it fills the prepared block, which can add a little delay, and a stable callback size re-prepares the plugins. **Null test** on the HOST page bypasses every plugin and the compensation delay so the output is that clean copy. The dB box after the slots is output gain from -9 to +9, default 0.0 dB. It is applied after the plugins, on the live and playback output only, and it is not written into the WAV. The corner line shows compensation delay and the USB round trip. **5 LATENCY** opens the full card: buffer size, driver input, driver output, compensation, round trip, dropouts, and the alignment mode.
- Right-click a channel to set an X32 scribble-strip color (Off, Red, Green, Yellow, Blue, Magenta, Cyan, White, and the inverted row) or to put it in one of 10 groups. Groups are view only: they do not change recording, routing, or plugins. Each group has its own name and X32 color, separate from the channels inside it. The group bar shows that color and name. Click the bar to fold or open its channels. Double-click the bar, or right-click it, to rename the group or change its color. **All** opens every group. **Hide** folds every channel that belongs to a group and leaves ungrouped channels visible. A folded bar still shows the loudest meter, clip, whether members are REC, OFF, or mixed, and FX if any member has a plugin. Colors, names, groups, and which groups are folded are saved in the session.
- `session.youhost` stores the device, the meter mode, the page, which channels are on, channel names and colors, groups, take positions, WAV names, the bit depth, the chains, bypass, exclude, and plugin state. Edits autosave only after a session folder exists. During a take the session file is rewritten every couple of seconds, and each WAV header is rewritten about once a second, so a crash still leaves playable files. When a file passes 4 GB, JUCE writes it as RF64 in the same `.wav` name. Launch does not reopen the last session by itself. The startup window lists recent sessions. A cold start stays on RMS until you open a session that was saved in Peak. YouHost does not create a folder until you create or open a session.
- **Dropouts** counts late callbacks, callbacks that outlast the buffer, and CoreAudio overload notifications. macOS does not report a usable xrun total through JUCE, so this counter replaces that. **Reset**, on the latency card and inside the dropout window, clears the count and the graph and writes a `reset` line in the log. The CSV file itself is kept. The count is kept across a buffer-size change; only the gap caused by reopening the device itself is ignored. **3 DROPOUTS** (or **Timeline** on the latency card, or the keys 3 and D) opens a timeline of the last 10 minutes, the last hour, or the whole session since reset. Each dropout is a red mark, with a CPU line behind it. The window shows the total, the time since the last dropout, the callback and per-plugin DSP load (only channels that have a plugin), and a green **STABLE** when the chosen range has none. The plugin list scrolls. **4 CPU** shows per-core meters, total CPU, and the audio callback. New dropouts are appended to `dropouts.csv` in the session folder, with the timeline position when a take was recording. The audio thread only drops a timestamp into a fixed ring. The file is written on the interface timer.

## Keys

These work from the recorder and plugin pages. They do not fire while a text field has focus. Cmd+S still saves from the File menu and while a plugin window is in front. **?** in the bottom-right corner shows the same list.

| Key | Action |
| --- | --- |
| 1 | REC page |
| 2 | HOST page |
| 3 or D | Open or close DROPOUTS |
| 4 | Open or close CPU |
| 5 | Open or close LATENCY |
| S | Open or close SCAN |
| Tab / Shift+Tab | Commit the channel name and edit the next or previous visible channel |
| Enter / Esc | Commit a channel name, or cancel it |
| Space | Play when stopped. If record is armed, start recording. Stop when playing or recording |
| Cmd+Space | Record a new take immediately |
| Cmd+S | Save the session |
| Cmd+Shift+S | Save a copy of the session folder |
| T | Zoom the timeline in |
| R | Zoom the timeline out until the whole session fits |
| Option+R | Fit every take in the timeline |
| Cmd+[ | Taller timeline lanes |
| Cmd+] | Shorter timeline lanes |
| Left / Right | Previous or next take marker |
| Shift+Left / Shift+Right | Move the playhead 5 seconds |

Cmd+Space only reaches YouHost if macOS Spotlight is not using that shortcut. Shift+Space does the same as Space. R zooms the timeline out until every take fits. Option+R, or the Fit button, shows the session from 0 to just past the last take and fits every visible lane. With no takes yet that view is 60 seconds. A full-scale peak fills the lane height. Quieter peaks use a dB curve. W+ and W- (or Cmd or Option plus the wheel over the lanes) zoom that waveform height. It is display only. v+ and v- (or Cmd+[ and Cmd+]) zoom the lanes taller and shorter. The plain scroll wheel moves through the lanes a little at a time. Shift plus the wheel scrolls time. While recording or playing, the cursor sits about three quarters of the way across the view. Drag the bottom edge of the timeline to change its height. 3, 4, 5, D, and S toggle their windows even when that window is in front. 1 and 2 still switch pages. REC, INPUT, and OFF are the channel modes. INPUT is heard and not recorded. The channel button cycles them. Audio setup ticks mean live or off.

The timeline draws one lane per recorded channel. A folded group is one lane. Color is only drawn where a take was recorded: each take is a block from its start to the sample it stopped, and empty time stays dark. A marker at each start reads TAKE and the number. While recording, that block grows. Lane numbers show only when the lane is tall enough to read. The channel color stays on the recorded waveform at every height, including a one-pixel line. Peaks are built on the disk thread. Double-click a channel name on the recorder or plugins page to edit it. Tab commits that name and edits the next visible channel. Shift+Tab goes back. Folded channels are skipped. Enter commits and leaves the editor. Esc cancels.

Bit depth sits between Sample rate and Audio buffer size, in Audio setup and in the startup window. The choice applies to the next take.

Network interfaces (AVB, Waves SoundGrid, Dante Virtual Soundcard or a Dante card, Behringer WING USB) use the same CoreAudio path. YouHost asks for up to 128 inputs and 128 outputs; channels past 128 are ignored, and input and output counts can differ. The device is remembered by name. If it is missing at startup, the startup window says it is not available and YouHost opens it when it appears. If it disappears during a session, recording stops cleanly, the WAV headers are flushed, a red **Audio device lost** banner is shown, and the same device is opened again when it comes back. REC/OFF and loaded plugins stay as they were. A sample-rate or buffer-size change re-prepares the plugins on the message thread and warns when the device rate does not match the session. Playback is not resampled.

If a plugin takes YouHost down, the next launch names it and offers **Leave them off** or **Load them anyway**. Those plugins are listed under Suspicious in the scanner. The notes are `youhost.log` and `crash-journal.txt` in `~/Library/Application Support/Ambient Audio/YouHost`. A plugin that needs a sidechain, or a layout that is not mono or stereo, is not loaded.

**Round trip on macOS.** JUCE 9's CoreAudio backend includes the hardware buffer in *both* the input latency and the output latency. Adding those two figures double-counts one buffer. YouHost shows the raw driver numbers, and the large round-trip figure is input + output − one buffer + compensation. Compensation here is the slowest included plugin chain, because that is how much later the desk hears the outputs. On ALSA the JUCE figure already omits one period, so the round trip adds the buffer back. This is still the driver's story plus the plugin delay, not a cable measurement.

## Build from source

Requirements: CMake 3.22 or newer, a C++20 compiler, and Ninja. macOS uses Xcode's command-line tools. Linux also needs the usual JUCE packages (`libasound2-dev`, Freetype, Fontconfig, X11, and GTK 3).

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
ctest --test-dir build --output-on-failure  # optional; the test binary is built either way
./build/YouHostTests
```

JUCE 9.0.3 is downloaded by CMake from the upstream release tarball. It is not vendored in this repository.

The app binary is under `build/YouHost_artefacts/`. On macOS that is `YouHost.app`. A universal build, matching CI, is:

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_OSX_ARCHITECTURES="arm64;x86_64" \
  -DCMAKE_OSX_DEPLOYMENT_TARGET=11.0
cmake --build build --parallel
codesign --force --sign - --timestamp=none build/YouHost_artefacts/Release/YouHost.app
```

`YouHostTests` does not open a sound card. It checks the passthrough, the meter ballistics, the 128-channel layout, dropout decisions, compensation arithmetic, take markers, WAV filenames, timeline zoom, and the session folder layout.

## Roadmap

The phases below follow the research notes.

| Phase | What it adds |
| --- | --- |
| P0 | Device picker, passthrough, meters, latency readout, dropout counter. In this tree. |
| P1 | Per-channel record enable, one disk thread, mono 16-bit, 24-bit, or 32-bit float WAV into the session `audio/` folder, header flush, timeline, and virtual soundcheck. This build. |
| P2 | Out-of-process AU/VST3 scan, four in-process slots per channel, editors, latency compensation, session folder, autosave. This build. A loaded plugin can still crash the app. |
| P3 | Sandbox processes for the slots, shared-memory audio, a short deadline with a dry fallback, restart after a crash. |
| P4 | Startup guard, disk-space and overrun warnings, loopback measurement. |
| P5 | Release packaging. Developer ID and notarization only if that cost is accepted later. |
| P6 | Windows, later. |

Recording taps the raw input on the audio thread and writes it on a disk thread, so a slow disk does not stall the plugins. The plugin sandbox is still later: a loaded plugin can crash the app, and the WAVs are what survive that.

## Try it on a desk

A useful first pass on an X32, or any multichannel USB interface:

- Confirm macOS shows the microphone prompt, and that all 32 inputs and 32 outputs appear.
- Set 48 kHz and step the buffer through the sizes the interface offers, especially the smallest ones you would actually use (often 64 and 128).
- Feed one channel at a time and check that the matching output, meter, and channel number follow it, and that the other outputs stay quiet.
- Clip one channel on purpose. The red mark stays lit through silence until you click it, or until you press Clear clips.
- Quit and launch again. RMS should be selected, with the bright 0 line across the bridge at line level. Peak should not come back until you open a session that was saved in Peak.
- Switch to Peak and check that the bright line moves to the top (0 dBFS) and the side numbers change. On a wide bridge the same numbers should be readable at both ends.
- Press 3, then Scan. The bar should move, ordinary plugins should appear before any shell, and De-Feedback should show as both AU and VST3 if both are installed. Waves shells stay out until **Scan Waves shells** is on. A failed plugin shows a reason, and the scanner processes should be gone when the scan finishes or after Stop. On page 2, AUGraphicEQ and a VST3 effect should both appear under their makers. All, AU, and VST3 filter the list. Instruments stay hidden, and the list says so. The top bar should show the same output count the device reports (a WING is 48 in and 48 out). Scan during a show can cause dropouts; the scanner says so. Click an empty slot, load De-Feedback, and confirm its window opens and the channel still returns on the same-numbered output. Click the slot to close the window, and right-click to bypass. Bypass should drop that slot's latency out of the chain.
- Put a different plugin on one channel only. Open Latency and check that the compensation figure rises by the slowest included chain. Press Ex on one row and confirm that channel stops moving the number.
- On launch, the startup window should appear first. Pick the interface, 48 kHz, and a buffer. Create a session on an external drive. Use **Internal disk…** only when you mean to store the session under `~/Music/YouHost/`, and confirm the warning. The folder should contain `session.youhost` and `audio/` before you record. Closing the window without a session should leave the status line on **No session** and should not create a Music folder. Click **Record**: it blinks red and does not start a take. Press **Play**: the counter turns red and a take grows from 0. **Stop** ends it and the blink stops. Press Cmd+Space for the next take. R and Shift+Space must not record. R zooms out, and Shift+Space plays or stops. The second take starts where the first ended. In `audio/`, expect one WAV per armed input, named `1_1.wav`, `2_1.wav`, or `1_1_BD.wav` when the channel has a name. Open **Audio setup** and confirm **Bit depth** says 24-bit unless you change it. The status line should show the same depth. Change it to 16-bit or 32-bit float, record another take, and confirm the new files use that depth while the first take is unchanged. With no take recording, the live input should still come out of the matching USB output. **File → New** should ask for a name and a folder, and Cancel should leave the old session untouched. Option-drag a plugin onto another channel and confirm the copy opens with the same settings. Resize Audio setup, the scanner, and a plugin list, quit, and confirm they come back the same size. The channel number should stay bold when you rename a channel and narrow the window. A channel color should tint the whole strip, and a group bar should show the group's own color and name. Press T and R, or the timeline + and − buttons: the waveform zooms and the playhead stays on screen. Cmd+S should save from the plugins page, with a plugin window in front, and from the menu bar.
- With record not armed, press Space. PLAYBACK shows. Every recorded channel that is still on, including channels with no plugin, comes out of the matching USB output. Channels with plugins run those plugins, and the dry channels are delayed so the outputs stay together. Click OFF on one channel: its meter stops, its output goes quiet, and the other channels stay in time. Click the middle of a take and press Space again to start there. Left and Right jump between takes. Shift+Left and Shift+Right move 5 seconds.
- Right-click a few channels, give them an X32 color, and put channels 1–8 in a group named Drums. Click the group bar, then Hide. Those channels fold, and channels with no group stay. All opens them again. The same bars are on the plugins page. Quit, open the session, and the colors and groups should return.
- Press Stop. The take stays on the timeline. Cmd+S, quit, and launch again. The startup window should appear, and RMS should be selected once you continue. Open the session from the recent list there, or later from File → Open Recent. The takes, chains, bypass, REC/OFF buttons, colors, groups, bit depth, and device should return, and Play should run the virtual soundcheck without recording again. The WAV files should still be in `audio/` even if you clear the timeline, and even if YouHost was force-quit during the take.
- Press 4. The dropout window should open on STABLE. Press Reset inside that window. The count and the graph clear, and `dropouts.csv` gains a line whose second field is `reset`. The older lines stay. Then try the smallest buffer. If the count climbs, the marks should sit on the graph. A disk warning means the WAV lost samples; the plugins should still have been running.
